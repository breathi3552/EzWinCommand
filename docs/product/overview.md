# EzWinCommand 产品契约

本文件只记录无法从代码可靠恢复、且未来变更必须保持或明确修改的稳定产品原则。接口清单、实现导航、普通功能列表和执行过程不属于本文件。

## 产品与安全边界

- EzWinCommand 面向 localhost 和可信局域网；公网和不受信任网络不在当前安全模型内。
- EzWinCommand 是单用户个人软件；所有已配对设备均视为由同一使用者控制，不设置普通设备与管理员设备的权限级别。
- Server 是设备身份、配对关系、命令执行和 Windows 状态的权威来源；网络地址变化不产生新的 Server 身份。
- Android 是主要移动控制体验；Web 保留本机管理和浏览器控制职责。
- 配对码和设备密钥属于敏感运行状态，不得进入仓库、普通日志或测试证据。
- 真实 Windows 系统能力和跨设备网络不能仅凭替身测试宣称完成；未取得环境证据时必须明确标为待验证。
- Server 与 Android 按同一协议版本配套升级；wire `protocol_version` 与 Server Identity 持久化 schema version 是独立事实；不兼容组合必须安全拒绝，能够识别版本差异的客户端必须明确提示升级，不保留含糊的旧字段别名。协议升级不得无故破坏已有配对关系，必要的非敏感状态迁移应自动完成。

## 发现、配对与设备关系

- 客户端可以发现 Server 或使用可信地址连接，但建立关系前必须确认目标 Server 身份，不能只信任广播名称或网络地址。
- 配对请求与已配对设备是不同概念：只有成功完成配对才产生设备关系和设备密钥；失败、锁定、取消或过期的请求不得获得访问权限。
- 远端客户端可以提交配对信息，但不能读取真实配对码；配对码和本机待处理配对请求只向 PC 本机管理界面开放，已配对设备管理不受此本机边界限制。
- 每个已配对设备使用独立密钥访问受保护能力，并可被单独重命名或撤销。设备管理公共接口只暴露稳定、非敏感且不具备鉴权能力的 `device_id`、名称、创建时间、最后活动时间和布尔 `is_current`；localhost 的所有条目 `is_current=false`，远端根据已鉴权请求设备计算。所有管理方均可按 `device_id` 管理全部设备；撤销必须使该设备后续请求和活动状态流失效。
- 本机管理事件只用于通知状态失效，不能携带配对码或设备密钥；客户端在断线恢复后重新读取权威快照。
- Android 只有在配对成功且设备会话安全保存后才能进入控制状态。
- Android 控制会话发生授权失效时，必须先重新读取目标 Server identity：同一 `server_id` 且已确认凭据失效才删除整个本地会话；身份不同或不可达时保留记录并显示身份/连接错误。控制页进入不可操作的终止错误态，不提供内联“重新配对”操作，用户仍可使用顶部返回。

## 命令与插件

- Server 只公开已启用且成功加载的插件动作；被禁用或加载失败的插件不可执行，错误必须保持局部隔离。
- 插件是由 Server 管理员在本机部署的受信任代码。远程插件市场、上传下载和不可信插件沙箱不在当前安全模型内。
- Android 可以依据 Server 声明动态呈现无参数动作和固定子动作按钮；输入表单、滑杆、实时状态、SSE 与自定义布局不属于通用 action metadata，媒体和 OLED 护屏等 rich card 继续由客户端内置。
- 短命令在普通请求内返回明确结果；长命令使用独立任务表达受理、执行和终结状态，初始请求断开不等于后台任务失败。
- 异步任务必须按设备隔离所有权，不向客户端泄露内部参数、诊断堆栈或其他设备的任务状态；服务重启和任务过期必须收敛为明确结果。
- 客户端在暂时断网后保留未终结任务，以便恢复查询；只有权威结果证明任务终结或不存在时才清除本地待处理状态。

## 媒体与音频

- 媒体状态以完整快照和单调修订号表达；SSE 负责发布后续变化，断线恢复和慢消费者均以最新权威状态优先。Android 断线时保留最后有效快照，后台静默退避重连，并在 SSE 重新建立后先请求恢复快照再应用后续事件；播放、暂停、上一首、下一首、音量及输入输出设备命令成功后均通过同一权威 Media Snapshot/SSE 路径最终收敛。
- Windows 媒体集成空闲时只等待真实 dirty event，不周期性重读未变化的媒体或音频状态；初始化失败使用可取消且有上限的指数退避；媒体初始化、恢复、封面读取或控制命令不得阻断基础 HTTP 可用性；迟到的旧媒体或封面结果不得覆盖较新的媒体状态。
- 没有活动媒体会话时，音量和默认输入、输出设备能力仍然独立可用。
- 撤销设备权限必须终止该设备的活动媒体事件流；客户端切换 Server、退出会话或销毁控制器后不得继续接受旧连接的状态，且必须停止重连、封面任务和迟到回调。
- Android 的音量拖动可即时显示并保留节流；命令失败回滚到最后确认值，成功后等待权威 SSE 快照收敛到 Windows 实际值。输入、输出设备在权威快照到达前保持原选择，失败不改变选择；媒体命令不自动重试。
- 用户可见错误保持简短并允许恢复；平台异常的详细诊断只保留在脱敏的 Server 日志中。

## Windows 集成与电竞模式

- Windows 媒体与 Core Audio 状态由受控的平台生命周期统一管理，API 层和客户端不直接持有平台对象。
- 防火墙、自启和托盘能力服务于当前登录用户的可信局域网控制体验，不承诺无人登录运行或系统服务语义。
- 电竞模式是有顺序的复合长任务。进入过程任一步失败时停止后续动作并报告首个有效错误；退出过程关闭受管通信和游戏进程、恢复目标音频环境，但不结束游戏平台本身。
- 提交外部应用 URI 或启动进程只表示操作已交付，不代表第三方 UI 已完成房间进入、登录或游戏加载。
- OLED 护屏通过 Windows 原生 `SC_MONITORPOWER` 启动 5 秒初始倒计时；倒计时到期后全局关闭活动显示器，再依据 `GUID_MONITOR_POWER_ON` 的 `WM_POWERBROADCAST` 亮起通知启动 60 秒倒计时并循环关屏。不使用 DDC/CI、Sleep/Hibernate 或 watchdog。
- Android 只提供进入护屏操作。护屏流程启动后监听键盘 Raw Input、电源状态通知和倒计时窗口；任意键盘 Key Down 或倒计时窗口“取消”按钮会结束整个循环，鼠标移动和普通点击不会取消。关屏后的第一个键盘唤醒按键也直接结束流程；鼠标唤醒则由显示器亮起通知启动下一轮 60 秒倒计时。
- 护屏不停止 Server、音频或网络，Server 重启不主动改变显示器状态；当前采用全局显示器电源行为，多显示器环境允许所有活动显示器一起关闭。

## 变更纪律

- 改变安全边界、设备关系、状态恢复、跨端协议原则或真实环境限制时，必须同步更新本文件和 `docs/tests/coverage-map.md`。
- 影响既有架构取舍的变更必须核对 `docs/adr/`；需要推翻决策时新增 ADR 并明确 supersede 关系，不能静默改写历史。
