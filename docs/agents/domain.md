# 项目知识分层

Engineering skills 探索代码库时，按本文件区分领域词汇、架构决策和产品契约，避免把不同层级写进同一文档。

## 探索时读取

按当前任务选择，不因文件存在就全部加载：

1. 命名领域概念时读取根目录 `CONTEXT.md`；若不存在，静默继续。
2. 涉及既有架构取舍时读取 `docs/adr/` 中相关 ADR；目录不存在时静默继续。
3. 改变用户行为、跨端协议、安全边界或 Windows 集成时读取 `docs/product/` 中相关契约。
4. 设计长期业务验证时读取 `docs/tests/coverage-map.md`。

## 职责

### `CONTEXT.md`：ubiquitous language

只保存领域术语、定义、关系、边界、排除项和示例。它不是功能规格、模块地图、实现说明或需求草稿。由 `skill://domain-modeling` 在首个术语真正确定后按需创建和维护。

### `docs/adr/`：架构决策

只记录同时满足以下条件的决定：难以逆转；缺少背景会让未来维护者困惑；存在真实替代方案与权衡。与 ADR 冲突的提案必须明确指出冲突，不得静默覆盖。

### `docs/product/`：稳定产品契约

保存无法从代码可靠恢复、且未来变更必须保持或明确修改的产品事实：职责边界、安全不变量、用户可观察的特殊行为、跨端 wire、错误与恢复语义、兼容边界和真实环境限制。

不维护普通功能清单、类/函数导航、调用方列表或过程流水账。

### 长期测试与版本资料

- `docs/tests/coverage-map.md` 记录稳定业务路径、验证层级、可复核证据和已知缺口，不缓存普通测试文件清单。
- `docs/versions/` 与 `docs/changelog.md` 记录新增、变更、修复、移除和待人工验证，不记录内部执行过程。

## 写入规则

- 术语确定时就地更新 glossary，不批量积压。
- 稳定产品或协议事实实际变化时更新对应产品契约；可从代码直接恢复的内部变化无需文档化。
- 使用 `CONTEXT.md` 已定义的术语命名 issue、spec、测试和设计；需要新词时先判断它是领域缺口还是自造语言。
