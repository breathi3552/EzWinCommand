# EzWinCommand 项目资料

`docs/` 保存需要跨任务延续的产品事实和测试资产，不再承担强制阶段流水线或为每个任务生成成套报告。

## 当前结构

```text
../CONTEXT.md       # EzWinCommand 领域词汇
docs/
├── adr/            # 难逆转、反直觉且有真实权衡的架构决策
├── agents/         # Skill 共用的 tracker、triage 与知识分层配置
├── product/        # 单一当前产品原则契约
├── tests/          # 长期高风险业务验收地图
├── versions/       # 轻量版本级变更日志
└── v*/             # 本机历史过程资料，不纳入版本控制，也不作为当前事实来源
```

## 维护原则

- 产品原则、安全边界或恢复语义变化时更新 `product/overview.md`。
- 长期高风险业务路径、验证层级或证据缺口变化时更新 `tests/coverage-map.md`；普通测试文件变动不触发文档更新。
- 用户可见变化、重要修复及待人工验证项写入当前版本日志。
- 临时计划、研究草稿和测试报告默认保留在 session 或 `local://`。
- 截图、UI dump、日志和临时报告属于运行证据，不作为正式产品文档提交。
- 历史 `v*/REQ-*` 仅作本机线索，不提交也不反向覆盖当前知识；只有经当前代码、测试或已确认产品意图验证的稳定事实，才能按知识分层重新表述。

工程路径由 `.omp/AGENTS.md` 与 `skill://ask-matt` 定义；知识分层与维护方式见 `docs/agents/domain.md`。
