# OMP 阶段边界

只在一个阶段完成、下一个阶段尚未开始时决定是否切换上下文。阶段中途继续推进；可独立的剩余切片可以交给子 Agent。

按顺序判断：

1. **继续是否最可靠？** 下一阶段需要本阶段的原始推理、用户决策或实时工具状态时，留在当前 session。
2. **工作是否可独立并行？** 只有输入、输出、验收和非目标都已明确时，使用 OMP `task`；读探索用 `scout`，审查用 `reviewer`，多个独立切片在一个 batch 中并行派发。
3. **信息是否必须跨 session、目录、harness 或人员移动？** 读取 `skill://handoff`，生成 `local://` 交接文档，并引用现有 primary sources。
4. **否则继续。** 不制造无收益的上下文切换。

## 来源成本

| 方式 | 保真度 | 隔离性 | 适用场景 |
| --- | --- | --- | --- |
| 当前 session | 最高 | 低 | 下一阶段依赖当前推理和工具状态 |
| OMP `task` | 由任务 brief 决定 | 高 | 可独立验收的并行切片 |
| `local://` handoff | 有损摘要 | 高 | 信息确实需要移动 |

Handoff 只携带下一阶段无法从代码、issue、spec、ADR、测试结果或 diff 恢复的内容。引用 primary sources，不复制它们。
